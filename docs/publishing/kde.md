# Publishing the KDE Plasma port

`ports/kde/*.colors` is four standalone Plasma colour-scheme files (`Darkberry Wisp.colors`, `Fen`, `Mire`, `Blackwater`), one per flavour, installed by copying into `~/.local/share/color-schemes/`; `ports/kde/<tint>/` holds the same four files re-derived for each of the four tints (lingonberry/cloudberry/crowberry/blueberry). This is the native Plasma "Colors" KConfig `.colors` format (`[General]`/`[Colors:...]` sections), not a packaged plugin — nothing to build or sign.

## Venues

### KDE Store (store.kde.org, backed by Pling/OpenDesktop)

- **URL**: https://store.kde.org/browse?cat=112 (category "Plasma Color Schemes", confirmed id via `https://store.kde.org/browse/cat/112/order/latest/`); upload form https://store.kde.org/product/add ; FAQ https://store.kde.org/faq-pling
- **Kind**: official gallery — this is the OCS (Open Collaboration Services) provider that Plasma's own "Get New Color Schemes…" button (KNewStuff) queries by default.
- **Accepts**: a product page with a title, description, category ("Plasma Color Schemes"), a licence field, one or more preview images, and one or more attached files (the `.colors` file(s), plain or archived — `plasma-workspace`'s `.knsrc` declares `Uncompress=archive`, so a `.zip`/`.tar.gz` of the four flavours, or four separate uploads, both work). A "source code" URL field should point at the repo (`https://github.com/shythulu/DarkBerry`) rather than being left blank, per community advice. Exact preview-image pixel dimensions are not documented anywhere found — **unverified**. Licence field: a dropdown of common OSI/libre licences; MIT-licensed products exist on the store (confirmed by search), so MIT is an accepted option, but the exact dropdown label for MIT was not directly observed — **partly verified**.
- **Requirements**: free registration ("Join" + email verification) at store.kde.org/identity.kde.org-backed account — no fee, no bank/PayPal details required just to list content. One discussion thread reported Gmail addresses being rejected at signup, with a Proton Mail address working as a workaround (unverified as still current). This store account is distinct from a KDE Identity / invent.kde.org developer account — no GitLab or KDE Identity account is needed just to upload here. Pling has an opt-in payout program (cents per valid download/view, per its terms) — unrelated to whether content can be listed for free; no evidence payout is mandatory.
- **Steps** (assembled from a first-hand forum account, since the store's own upload UI could not be fetched — an anti-bot wall (Anubis) blocked automated retrieval of store.kde.org and opendesktop.org pages):
  1. Register/sign in at store.kde.org (or pling.com/opendesktop.org — same backend, "Pling hosts and runs the KDE Store; store.kde.org is basically a KDE-themed front-end to pling.com" per a KDE developer).
  2. Go to https://store.kde.org/product/add.
  3. Fill the multi-step form: title (e.g. "Darkberry"), category "Plasma Color Schemes", description (can reuse the port README text), licence (MIT), source-code URL (the GitHub repo), tags.
  4. Upload preview image(s) — the flavour preview screenshots already in `ports/kde/assets/` (`wisp.webp`, `fen.webp`, `mire.webp`, `blackwater.webp`, `preview.webp`) are candidates, though their format may need converting from `.webp` if the uploader requires PNG/JPG (unverified).
  5. Attach the `.colors` file(s) as the downloadable content.
  6. Submit/publish.
- **Updates**: edit the same product page and upload a new file version; KNewStuff's "Get New Color Schemes" in System Settings picks up new products within minutes of publishing (per forum report re: Dolphin's "New Stuff", same backend) and shows updates for anyone who already installed it.
- **Contacts**: store.kde.org's own comment/support channels on the product page; general KDE Discuss forum https://discuss.kde.org (categories "Development"/"Community"); no dedicated store-support email found.
- **Sources**: https://discuss.kde.org/t/how-to-upload-to-kde-store/36690 (fetched 2026-09-24); https://discuss.kde.org/t/pling-vs-kde-store-best-pratices-on-explaining-to-others/40127 (fetched 2026-09-24, quotes Nate Graham); https://invent.kde.org/plasma/plasma-workspace/-/raw/master/kcms/colors/colorschemes.knsrc (fetched 2026-09-24 — confirms `TargetDir=color-schemes`, `Categories=KDE Color Scheme KDE4`, `UploadCategories=KDE Color Scheme KDE4`, `AdoptionCommand=plasma-apply-colorscheme %f`); https://store.kde.org/browse?cat=112 search-result title (2026-09-24); search snippets referencing store.kde.org/faq-pling registration/payout text (2026-09-24, page itself blocked by Anubis anti-bot on direct fetch).
- **Confidence**: partly verified. The category, KNewStuff wiring, free registration, and general upload flow are corroborated by two independent sources. Exact upload-form field names, preview-image size/format requirements, and the precise licence-dropdown entries could not be directly observed (store.kde.org blocked automated fetches) — flagged unverified above; a submitting agent should open `store.kde.org/product/add` in a real browser to confirm before submitting.

## Not applicable

- **Upstream `plasma-workspace` or `breeze` (KDE Invent/GitLab)**: checked https://invent.kde.org/plasma/breeze and https://invent.kde.org/plasma/plasma-workspace. These repos ship KDE's own default/first-party schemes (Breeze, Breeze Dark, etc.); third-party community colour schemes are the KDE Store's job, not upstream's — the `.knsrc` file itself exists precisely to pull community content from the Store rather than bundling it in the repo. One precedent merge request adding a community-proposed "Twilight" global theme to `breeze` (https://invent.kde.org/plasma/breeze/-/merge_requests/45, opened 2020-10-22) shows this path is at least occasionally discussed, but no merged precedent for a full third-party colour-scheme set was found, and that MR's outcome could not be determined from the page. Treat upstream inclusion as not a normal distribution channel for this port.
- **gnome-look.org / xfce-look.org / other Pling-network sites**: same OCS backend as store.kde.org but for different desktop environments (GNOME, Xfce); not applicable since this port targets Plasma specifically and store.kde.org already covers the Plasma "Get New" pipeline.
