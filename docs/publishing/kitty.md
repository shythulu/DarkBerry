# Publishing the kitty port

`ports/kitty/` holds one `.conf` per flavour (`darkberry-wisp.conf`, `darkberry-fen.conf`, `darkberry-mire.conf`, `darkberry-blackwater.conf`) at the folder root, plus the four tints (Lingonberry, Cloudberry, Crowberry, Blueberry) each in their own subfolder with the same four flavour files renamed to `<tint>-<flavour>.conf`. Each file is a plain kitty config using kitty's own `## name:` / `## license:` / `## blurb:` metadata-comment header followed by `key value` colour settings (no external build step; the `.conf` file itself is the distributable artifact).

## Venues

### kitty-themes (official collection)

- **URL**: https://github.com/kovidgoyal/kitty-themes
- **Kind**: official gallery — this is the repo kitty's built-in `kitty +kitten themes` picker downloads from; it is also linked from kitty's own docs at https://sw.kovidgoyal.net/kitty/kittens/themes/.
- **Accepts**: one `.conf` file per theme dropped in the repo's `themes/` directory (files live flat, not in per-family subfolders). Header metadata: `## name:` (required — theme display name, must be unique across the whole repo; "Darkberry Wisp"/"Fen"/"Mire"/"Blackwater" are free as of 2026-09-24), `## author:` (optional, not currently set in Darkberry's files), `## license:` (their `gen-metadata.py` normalizes known spellings — plain `MIT` is recognised as-is, which matches what Darkberry's files already say), `## upstream:` (optional URL for auto-updates — could point at the raw GitHub URL of each file in this repo), `## blurb:` (optional, must be the last metadata field, can span lines). No enforced filename convention: some contributions use `Family-Variant.conf` (e.g. `Catppuccin-Frappe.conf`), others `family-variant.conf` (e.g. `rose-pine-dawn.conf`); Darkberry's existing `darkberry-mire.conf` style fits. No screenshot file is required in the PR itself (a screenshot is only asked for in the separate "theme request" issue template, for when someone else is asked to add a theme on your behalf).
- **Requirements**: a GitHub account to fork and open a PR; no CLA, no fee, no signing key, no 2FA requirement stated. Review is manual, by maintainer kovidgoyal (recent merged PRs are small, single-theme, no extra process).
- **Steps**:
  1. Fork https://github.com/kovidgoyal/kitty-themes.
  2. Copy each Darkberry flavour `.conf` into `themes/` (base `template.conf` at the repo root is the reference for the header format, but Darkberry's files already follow it).
  3. Keep filenames unique and non-colliding with existing themes in `themes/`.
  4. Commit and open a pull request against `master`.
  5. Maintainer reviews and merges directly (no CI checks were found in `.github/workflows`; `gen-metadata.py`/`themes.json` are regenerated by the maintainer's own tooling, not by contributor-run CI).
- **Updates**: kitty's `themes` kitten fetches the whole repo as a zip from `https://codeload.github.com/kovidgoyal/kitty-themes/zip/master` and caches it locally (`--cache-age`, default ~1 day per `main.py`/`main.go`). Once a PR is merged to `master`, users see it after their local cache expires or they run `kitty +kitten themes --reload`. A later fix is just another PR editing the same `.conf` file.
- **Contacts**: issues/PRs at https://github.com/kovidgoyal/kitty-themes/issues and /pulls; overall kitty project at https://github.com/kovidgoyal/kitty.
- **Sources**: https://github.com/kovidgoyal/kitty-themes (2026-09-24), https://raw.githubusercontent.com/kovidgoyal/kitty-themes/master/README.rst (2026-09-24), https://raw.githubusercontent.com/kovidgoyal/kitty-themes/master/template.conf (2026-09-24), https://raw.githubusercontent.com/kovidgoyal/kitty-themes/master/gen-metadata.py (2026-09-24), https://api.github.com/repos/kovidgoyal/kitty-themes/contents/themes (2026-09-24, naming survey), https://raw.githubusercontent.com/kovidgoyal/kitty-themes/master/themes.json (2026-09-24, name-collision check), https://raw.githubusercontent.com/kovidgoyal/kitty/master/tools/themes/collection.go (2026-09-24, cache/update mechanism), https://sw.kovidgoyal.net/kitty/kittens/themes/ (2026-09-24).
- **Confidence**: verified (metadata format, filename freedom, update mechanism, and process all confirmed from primary sources). Unverified: typical PR review turnaround time, and whether a maintainer would ask for all 4 flavours + 16 tint variants in one PR or prefer them split.

### mbadolato/iTerm2-Color-Schemes (community multi-terminal repo)

- **URL**: https://github.com/mbadolato/iTerm2-Color-Schemes
- **Kind**: community repo — a very widely used curated collection covering iTerm2, Kitty, Alacritty, Ghostty, Windows Terminal, Konsole, and dozens more, each generated from one canonical source file.
- **Accepts**: contributors do not add a kitty `.conf` file directly. The source of truth is either an iTerm `.itermcolors` export placed at `schemes/<Your Theme Name>.itermcolors`, or (for a non-iTerm source like Darkberry's kitty `.conf`) a YAML file in the Gogh-derived format placed at `yaml/<Your Theme Name>.yml`; the repo ships a `tools/kitty_to_yaml.py` converter that reads a kitty `.conf` on stdin and emits the YAML fragment. The kitty export under `kitty/` is then generated by their `tools/gen.py -t kitty` from that YAML/itermcolors source — it is not hand-written or PR'd directly. Filenames must exactly match the human-readable theme name (no slugifying, spaces kept). A generated screenshot (`tools/screenshot_gen`) and an optional `CREDITS.md` entry are part of the PR.
- **Requirements**: GitHub account; local Python (via `pyenv`/`requirements.txt`) or Docker to run the generation/screenshot tooling before opening the PR. No fee, no signing key, no 2FA stated.
- **Steps**:
  1. Fork the repo.
  2. Convert one Darkberry flavour `.conf` with `tools/kitty_to_yaml.py < darkberry-mire.conf > "yaml/Darkberry Mire.yml"` (repeat per flavour), or hand-write the YAML per `yaml/README.md`.
  3. Run `python3 tools/gen.py -s "Darkberry Mire"` to generate the kitty/other-terminal exports.
  4. Optionally run `tools/wcag_check.py` (failing is non-blocking) and `tools/screenshot_gen` to produce the screenshot.
  5. Optionally add a `CREDITS.md` line.
  6. Open a PR; the README's `SCREENSHOTS_BEGIN`-delimited section of `README.md` is regenerated by their tooling.
- **Updates**: same flow — edit the `yaml/`/`schemes/` source, regenerate, open a new PR.
- **Contacts**: issues/PRs at https://github.com/mbadolato/iTerm2-Color-Schemes/issues and /pulls.
- **Sources**: https://raw.githubusercontent.com/mbadolato/iTerm2-Color-Schemes/master/README.md (2026-09-24), https://api.github.com/repos/mbadolato/iTerm2-Color-Schemes/contents/ (2026-09-24, confirms a `kitty/` output directory exists), https://raw.githubusercontent.com/mbadolato/iTerm2-Color-Schemes/master/LICENSE (2026-09-24, MIT).
- **Confidence**: partly verified — the contribution workflow and YAML template are read directly from their docs, but the exact shape of `tools/kitty_to_yaml.py`'s output and how faithfully it round-trips Darkberry's kitty-specific extras (tab/border/mark colours, which the 16+3-colour Gogh format doesn't have fields for) was not test-run.

### Gogh (Gogh-Co/Gogh)

- **URL**: https://github.com/Gogh-Co/Gogh
- **Kind**: community repo — a curated colour-scheme collection/installer with an `apply_kitty()` function in `apply-colors.sh` that writes a kitty `colors.conf` and includes it from `kitty.conf`.
- **Accepts**: a single YAML file at `themes/<Your Theme Name>.yml` in Gogh's own (Dracula-derived) format: `name`, `author`, `variant` (`dark`/`light`, lowercase), `color_01`..`color_16` (the 16 ANSI colours), `background`, `foreground`, `cursor`. All hex values must be uppercase. Filename must exactly match the `name:` field, no underscores in the name. `task validate` runs the same checks CI runs (filename/name match, no underscores, valid `variant`, uppercase hex, PR touches only `themes/`); foreground/background contrast ≥2.5:1 is recommended but not enforced. PR title must start with `theme:`.
- **Requirements**: GitHub account; `task` (Taskfile) and `uv` installed locally to run `task init`/`task generate`/`task validate`. No fee, no signing key, no 2FA stated. All other generated files (`data/`, `installs/`, `gogh.sh`, `tools/run.txt`) are produced by CI after merge — contributors must not hand-edit or commit them (a git hook from `task init` blocks it).
- **Steps**:
  1. Fork the repo, run `task init` once.
  2. Add `themes/Darkberry Mire.yml` (repeat per flavour) using the field reference above, converting Darkberry's kitty hex values into the 16+3 slot layout.
  3. Optionally `task generate` to preview, then `task clean` to discard the generated files before committing.
  4. `task validate TITLE="theme: Add Darkberry Mire"` to self-check.
  5. Open a PR titled `theme: Add Darkberry Mire` touching only `themes/`.
- **Updates**: edit the same `themes/<name>.yml` and open a new PR; CI regenerates everything else after merge.
- **Contacts**: issues/PRs at https://github.com/Gogh-Co/Gogh/issues and /pulls.
- **Sources**: https://raw.githubusercontent.com/Gogh-Co/Gogh/master/docs/CONTRIBUTING.md (2026-09-24), https://raw.githubusercontent.com/Gogh-Co/Gogh/master/README.md (2026-09-24, confirms Kitty is a supported `apply_kitty()` target), https://raw.githubusercontent.com/Gogh-Co/Gogh/master/apply-colors.sh (2026-09-24).
- **Confidence**: partly verified — submission process is fully documented, but Gogh's 16+3 colour model is lossier than kitty's own format (no tab bar, border, mark, or 256-colour palette fields), so a submitting agent will have to choose a lossy reduction; not tested end-to-end.

## Not applicable

- **dexpota/kitty-themes** (https://github.com/dexpota/kitty-themes) — the predecessor collection kovidgoyal/kitty-themes was originally imported from; not archived but no longer wired into kitty's own `+kitten themes` picker or docs, so it has no reach beyond direct GitHub visitors. Checked its repo metadata (`archived: false`, recent pushes) but it isn't referenced anywhere in current kitty tooling — skip in favour of the official repo.
- **Official app store / marketplace** — kitty has no plugin or theme marketplace of its own (unlike, e.g., a VS Code Marketplace); its only in-app distribution channel is the `kitty +kitten themes` picker backed by kitty-themes above. Checked https://sw.kovidgoyal.net/kitty/kittens/themes/ and the kitty docs site nav; no other listing exists.
- **Package registries** (Homebrew, apt, PyPI, npm, etc.) — kitty themes are plain config files, not packaged/distributed through any package manager; checked kitty's own docs and found no such mechanism for themes specifically (only kitty itself is packaged that way).

- Whose GitHub account opens the PRs (shythulu's own, presumably, per repo attribution) — confirm before submitting anywhere that needs a fork.
- For iTerm2-Color-Schemes and Gogh, whether it's worth accepting the lossy reduction (both formats drop kitty-specific tab/border/mark colours) versus skipping those two venues and relying on kitty-themes as the primary distribution point.
