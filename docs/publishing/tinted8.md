# Publishing the Tinted8 port

`ports/tinted8/` holds one Tinted8 scheme YAML per flavour at the folder root (`darkberry-wisp.yaml`, `darkberry-fen.yaml`, `darkberry-mire.yaml`, `darkberry-blackwater.yaml`), plus the four tints (Lingonberry, Cloudberry, Crowberry, Blueberry) each in their own subfolder as `<tint>-<flavour>.yaml`. Each file is a Tinted8 styling-spec scheme (`scheme.system: tinted8`, `scheme.supports.styling-spec`, `variant`, an eight-anchor `palette`, and full `syntax` and `ui` blocks written in the key names `tinted-builder-rust` actually accepts) for Tinted Theming's Tinted8 builders.

## Venues

### tinted-theming/schemes (`tinted8/` directory)

- **URL**: https://github.com/tinted-theming/schemes — files land in `tinted8/` at the repo root. Its default branch is `spec-0.11`; there is currently no `main` branch on this repo.
- **Kind**: official community repo / canonical scheme registry — every current Tinted Theming builder and downstream tool (`tinty`, `tinted-builder-rust`, Tinted Studio's scheme snapshot) reads schemes from this one repo.
- **Accepts**: Tinted8 scheme YAML — confirmed live: a `tinted8/` directory already exists with 4 files (`catppuccin-latte.yaml`, `catppuccin-mocha.yaml`, `gruvbox-dark.yaml`, `nord.yaml`), added in PR #100 ("Add initial tinted8 schemes") and corrected in #101/#102. All three PRs were opened and merged by the project's own maintainer (JamyGolden); no outside contributor has added a Tinted8 scheme yet, while every other recent merged PR (#103–#124) adds base16/base24 schemes only.
- **Requirements**: a GitHub account to fork and open a PR. No CLA/DCO found. The repo is MIT-licensed (`LICENSE`); there is no separate inbound-licence statement for contributions — MIT (which Darkberry already is) matches the repo's own licence, but this is convention, not a written rule. A file must satisfy `.yamllint.yml` (`extends: default`, line length max 180, `document-start`/`comments` rules disabled) and `.editorconfig` (2-space indent, LF, final newline, no trailing whitespace); Darkberry's generated files already satisfy both (no line exceeds 180 characters, each file ends with one trailing newline). Note: `scripts/lint`, which the `Test` CI workflow also runs, hardcodes `supported_schemes_systems="base16 base24"` and never touches `tinted8/`, so nothing in CI validates a Tinted8 file's required fields — correctness is down to maintainer review only.
- **Steps**:
  1. Fork https://github.com/tinted-theming/schemes.
  2. Copy `ports/tinted8/darkberry-*.yaml` into `tinted8/` at the repo root, unchanged — the filenames already match the `<family>-<style>.yaml` convention the existing `tinted8/`, `base16/` and `base24/` files use.
  3. Run `yamllint .` locally to confirm no regressions. The CI `Test` workflow triggers on PRs targeting branches matching `spec-**`, which the repo's only branch, `spec-0.11`, matches, so it will run automatically on the PR.
  4. Commit, push to the fork, and open a PR against `tinted-theming/schemes:spec-0.11` describing the family, its four flavours, and linking the Darkberry repo/site.
  5. A maintainer (CODEOWNERS team `@tinted-theming/schemes`) reviews and merges. Recent base16/base24 PRs merge within days to a few weeks; no Tinted8-specific precedent exists for review turnaround since all four existing files came from the maintainer directly.
- **Updates**: edit the same file(s) in a follow-up PR — the exact pattern PR #101 and #102 used to fix two Tinted8 field names after #100 merged.
- **Contacts**: issues/PRs at https://github.com/tinted-theming/schemes (CODEOWNERS `@tinted-theming/schemes`; maintainer active on recent merges is JamyGolden, https://github.com/JamyGolden). Broader project chat is the Matrix room `#tinted-theming:matrix.org` (linked from `tinted-theming/home`'s CONTRIBUTING.md). Ecosystem-wide questions can also go to https://github.com/tinted-theming/home/issues.
- **Sources**: https://github.com/tinted-theming/schemes (root, README.md, LICENSE, .yamllint.yml, .editorconfig, .github/CODEOWNERS, .github/workflows/test.yml, scripts/lint — read 2026-09-24); https://github.com/tinted-theming/schemes/tree/spec-0.11/tinted8 (2026-09-24); https://github.com/tinted-theming/schemes/pull/100, /pull/101, /pull/102 (2026-09-24); https://github.com/tinted-theming/schemes/pull/124 and /pull/122 (external-contributor process precedent, 2026-09-24); https://github.com/tinted-theming/home/blob/main/specs/tinted8/styling.md (spec header read "Version 0.2.0-beta11" on 2026-09-24) and /blob/main/CONTRIBUTING.md.
- **Confidence**: partly verified — the directory, file format, and fork-and-PR process are verified against the live repo and merged PRs; the actual review bar and turnaround for a first outside-contributor Tinted8 PR are unverified, since all four existing Tinted8 files were added by the maintainer, not a community contribution.

## Not applicable

- Tinted Gallery (https://tinted-theming.github.io/tinted-gallery/, source https://github.com/tinted-theming/tinted-gallery) — `build.sh` only calls `generate_themes "base16"` and `generate_themes "base24"`; it clones `tinted-theming/schemes` and walks `schemes/base16/*.yaml` and `schemes/base24/*.yaml` only, never `schemes/tinted8/`. No Tinted8 scheme is shown here today (confirmed by reading `build.sh`, 2026-09-24).
- Tinted Studio (https://tinted-theming.github.io/studio/, source https://github.com/tinted-theming/studio) — a client-only scheme *authoring* tool whose README says it can craft/export Base16, Base24, and Tinted8 schemes; it ships a local snapshot (`data/schemes.json`) generated by `scripts/refresh-schemes.sh` from `tinty list --json`. It is not a submission target — nothing is opened or filed there — and would only start listing Darkberry once (a) the scheme merges into `tinted-theming/schemes` and (b) someone reruns that refresh script.
- The ~70 per-application template repos (e.g. `tinted-claude-code`, which explicitly supports Base16/Base24/Tinted8 input) — these are downstream builders that consume whatever is in `tinted-theming/schemes`; there is nothing to submit to them directly.
- No repository literally named `tinted8` exists in the `tinted-theming` GitHub org (checked the full org repo listing, 2026-09-24); the spec lives inside `tinted-theming/home` at `specs/tinted8/styling.md` and `specs/tinted8/builder.md`, which is documentation, not a submission venue.
- `tinted-theming/basenext` ("DRAFT version of BaseNext style specification") — a separate, unrelated draft spec, not Tinted8's home; not a submission target.

## Open questions

- Whether to open a Discussion/issue first, given no outside contributor has added a Tinted8 scheme before, or just submit a normal PR the way base16/base24 contributors do — nothing in the docs treats Tinted8 as needing a different process.
- Whether to submit all four flavours in one PR (matches PR #100's precedent, which added four families' worth of Tinted8 files together) or split per flavour.
- Whether to include the four tint subfolders (`ports/tinted8/<tint>/`) in the same PR or hold them back for a follow-up — none of the existing `tinted8/` files in the target repo represent a tint/family beyond a single base scheme.
- The existing `tinted8/` example files use only `palette` and `syntax` (no `ui` block at all) and declare `supports.styling-spec: "0.2.0"`, while `tinted-theming/home`'s spec header currently reads "Version 0.2.0-beta11" (as of 2026-09-24) — worth flagging in the PR description that Darkberry's files are the first to fill the full `ui` block, in case a maintainer wants that called out or wants the `supports.styling-spec` string revisited.
- No explicit inbound-licence statement was found for `tinted-theming/schemes` contributions (same gap noted for the Base24 port) — confirm MIT is acceptable as-is, or ask in the PR.
