# Publishing the Konsole port

`ports/konsole/*.colorscheme` holds one INI-format `.colorscheme` file per flavour (`Darkberry Wisp.colorscheme`, `Darkberry Fen.colorscheme`, `Darkberry Mire.colorscheme`, `Darkberry Blackwater.colorscheme`), each with a `[General]` block (`Description=`, `Opacity=1`, `Wallpaper=`) plus `Background`/`Foreground`/`Color0`–`Color7` (and Faint/Intense variants) blocks; the four tints (lingonberry, cloudberry, crowberry, blueberry) repeat the same shape in their own subfolders. MIT-licensed, generated by `build.mjs` from `src/ports/konsole.colorscheme` — do not hand-edit the port files.

## Venues

### KDE Store (Pling / store.kde.org)

- **URL**: https://store.kde.org/browse?cat=462&tag=color-scheme (the "Konsole Color Schemes" category, id `462`; the same listing also appears at https://opendesktop.org/browse?cat=462, part of the same Pling/OCS backend). Submission happens on https://pling.com (account menu → "My Products" from store.kde.org redirects there) or via https://store.kde.org/product/add.
- **Kind**: official store/marketplace, and it is wired into the app itself — Konsole's Settings > Edit Current Profile > Appearance has a "Get New…" button (a KNewStuff/GHNS dialog) that browses and installs directly from this store.
- **Accepts**: a downloadable archive containing `.colorscheme` file(s); a title, description, license, category, and at least one preview image. Exact preview pixel dimensions are unverified — Anubis anti-bot protection on store.kde.org and pling.com blocked automated fetches of the upload form's field-level requirements. Existing entries (e.g. "Campbell", store.kde.org/p/1650371) show one preview image and a short description is normal.
- **Requirements**: a free Pling/store.kde.org account (separate from a KDE Identity/GitLab account). One forum report claims Gmail addresses are sometimes rejected at signup — unverified, treat as a fallback if signup fails. No fee to list; Pling pays creators a small amount per download/view rather than charging them. No formal review gate reported — GHNS listings there show up for other users "within minutes to hours."
- **Steps** (from a KDE Discuss thread and an OpenDesktop forum thread, see Sources):
  1. Create a Pling/store.kde.org account.
  2. Browse to the target category first — https://pling.com/browse?cat=462 (Konsole Color Schemes) — then use that category page's "Add Product" link. The category dropdown on the generic product-creation form is missing many categories including this one, so starting from the category page is required to pre-fill it correctly.
  3. Fill the three-step Pling upload form: title (e.g. "Darkberry"), a GitHub link in the *source code* field (not the homepage field) pointing at `https://github.com/shythulu/DarkBerry`, license (MIT), description, and at least one preview image.
  4. Attach the `.colorscheme` file(s) as the downloadable content — either one product per flavour or one product bundling all four with the four tints, submitter's choice (unverified which Pling itself recommends).
- **Updates**: edit the existing product on pling.com and upload a new file version; no separate re-review reported for updates to an already-listed product.
- **Contacts**: KDE Discuss (https://discuss.kde.org, category "Development"/"Store"), the OpenDesktop community forum (https://forum.opendesktop.org).
- **Sources**: https://discuss.kde.org/t/how-to-upload-to-kde-store/36690 (2026-09-24), https://forum.opendesktop.org/t/missing-categories/20240 (2026-09-24), https://forum.manjaro.org/t/cant-download-other-color-scheme-in-konsole/111378 (2026-09-24), https://store.kde.org/p/1650371 (2026-09-24).
- **Confidence**: partly verified — the account/category/upload-field mechanics come from community threads, not store.kde.org's own submission page, which returned an anti-bot block (Anubis) on every automated fetch attempt today. Preview image sizing is unverified.

### Konsole upstream bundle (KDE Invent)

- **URL**: https://invent.kde.org/utilities/konsole, color schemes live at `data/color-schemes/*.colorscheme` (mirrored read-only at https://github.com/KDE/konsole/tree/master/data/color-schemes).
- **Kind**: official gallery — these ship inside every Konsole install, no download needed.
- **Accepts**: a `.colorscheme` file in the same INI format Darkberry already uses (confirmed by comparing Darkberry's own `[General]` block — `Description=`, `Opacity=1`, `Wallpaper=` — against upstream's `Breeze.colorscheme`, which has the identical three keys and no `Author` field). Filed directly under `data/color-schemes/`, one file per scheme, named to match its `Description`. Precedent: merge request !1046 added a single new bundled scheme ("Campbell", from Microsoft's Windows Terminal) this way.
- **Requirements**: a KDE Identity account (https://identity.kde.org) with a real-name-like username, and 2FA (Webauthn or TOTP) enabled for KDE developer accounts; fork the project on invent.kde.org, then open a merge request. Konsole itself is GPL-2.0-or-later; whether upstream will take MIT-licensed data files as-is, or wants relicensing/a note, is an open question — the project's `REUSE.toml` has no per-file license declaration for `data/color-schemes/*.colorscheme`, so there's no established precedent either way to point to.
- **Steps**:
  1. Create a KDE Identity account and enable 2FA.
  2. Fork `utilities/konsole` on invent.kde.org (Fork button, public visibility).
  3. Add the fork as a git remote, branch off `master` (not on `master` itself), add the `.colorscheme` file(s) under `data/color-schemes/`.
  4. Commit with a descriptive message, push to the fork, open a merge request against `utilities/konsole`.
  5. Address maintainer review feedback (amend/push to the same branch); a maintainer merges once approved.
- **Updates**: same merge-request flow for any later fix; a bundled scheme only changes for users on their next Konsole/distro update, unlike the Store's on-demand download.
- **Contacts**: merge requests and issues at https://invent.kde.org/utilities/konsole, KDE Identity support at https://identity.kde.org.
- **Sources**: https://community.kde.org/Infrastructure/GitLab (2026-09-24), https://invent.kde.org/utilities/konsole/-/merge_requests/1046 (existence confirmed via search index, 2026-09-24; the MR page itself is behind an Anubis bot-block and could not be read directly), https://github.com/KDE/konsole/tree/master/data/color-schemes (2026-09-24), Darkberry's own `ports/konsole/Darkberry Wisp.colorscheme` compared against upstream `Breeze.colorscheme`.
- **Confidence**: partly verified — the KDE Identity/GitLab workflow is verified from KDE's own community wiki; the color-scheme-specific submission norms (naming, no author field) are inferred from the file format and one search-confirmed precedent MR, not from a written CONTRIBUTING policy (none was found at `CONTRIBUTING.md` in the repo root — 404).

### iTerm2-Color-Schemes (community repo)

- **URL**: https://github.com/mbadolato/iTerm2-Color-Schemes, Konsole output lives at `konsole/*.colorscheme` in that repo.
- **Kind**: well-known third-party curated repo — one of the largest cross-terminal theme collections (20+ target formats including Konsole, kitty, Alacritty, Windows Terminal, VS Code).
- **Accepts**: it does *not* take a pre-built `.colorscheme` directly. Contributors supply one canonical source file — either an iTerm2 `.itermcolors` export at `schemes/<Theme Name>.itermcolors`, or a YAML file at `yaml/<Theme Name>.yml` (their own extension of the Gogh project's format) — named with the exact human-readable display name (no slugifying, no underscores). The repo's `tools/gen.py` then *generates* the `konsole/<Theme Name>.colorscheme` file (and everything else) from that source, plus an optional WCAG contrast check (`tools/wcag_check.py`, 1.75:1 minimum — failing is tolerated) and a generated screenshot (`tools/screenshot_gen`).
- **Requirements**: a GitHub account; no fee, no signing. Local tooling to contribute: Python (pinned via `.python-version`/`pyenv`) and `pip install -r requirements.txt`, or a Docker-based `generate-all.sh` that does the same without local Python.
- **Steps**:
  1. Produce a `schemes/Darkberry <Flavour>.itermcolors` (or `yaml/Darkberry <Flavour>.yml`) file per flavour from Darkberry's palette — this is new authoring work, not a copy of the existing Konsole port.
  2. Run `python3 tools/gen.py -s "Darkberry <Flavour>"` to generate the Konsole file (and all other targets) from it.
  3. Optionally run `tools/wcag_check.py` and the screenshot generator.
  4. Update `README.md` (theme list + screenshot) and optionally `CREDITS.md`.
  5. Open a pull request.
- **Updates**: same PR flow — edit the canonical `.itermcolors`/YAML source and regenerate, rather than hand-editing the generated `konsole/*.colorscheme` output.
- **Contacts**: issues/PRs at https://github.com/mbadolato/iTerm2-Color-Schemes.
- **Sources**: https://github.com/mbadolato/iTerm2-Color-Schemes/blob/master/README.md (fetched in full, 2026-09-24).
- **Confidence**: verified.

### AUR (Arch User Repository)

- **URL**: https://aur.archlinux.org, package pages e.g. `aur.archlinux.org/packages/<name>`. Precedent exists for exactly this kind of port: `catppuccin-konsole-colorscheme-git` is already an AUR package, alongside `konsole-gruvbox` and `konsole-monokai`.
- **Kind**: package registry (distro-level), Arch/Manjaro-specific.
- **Accepts**: a `PKGBUILD` (+ generated `.SRCINFO`) that installs the `.colorscheme` file(s) to `/usr/share/konsole/`; package name convention seen in precedent is `<theme>-konsole-colorscheme[-git]`.
- **Requirements**: a free AUR account with an SSH public key uploaded to the account for git push access over `ssh://aur@aur.archlinux.org`. No review gate before publishing (anyone can push a new package instantly), but ongoing maintenance is the submitter's own responsibility — an unmaintained/broken package can eventually be orphaned or flagged by other users.
- **Steps**:
  1. Create an AUR account and add an SSH public key to it.
  2. Configure SSH (`Host aur.archlinux.org`, `User aur`, matching `IdentityFile`).
  3. `git clone ssh://aur@aur.archlinux.org/<pkgname>.git`, add `PKGBUILD` (sourcing the `.colorscheme` files, e.g. from the GitHub release or repo tag) and generate `.SRCINFO` with `makepkg --printsrcinfo > .SRCINFO`.
  4. `git add PKGBUILD .SRCINFO`, commit, `git push` (AUR only accepts pushes to `master`).
- **Updates**: bump `pkgver`/`pkgrel` in `PKGBUILD`, regenerate `.SRCINFO`, commit and push again.
- **Contacts**: AUR package comment threads on each package page; general AUR help at https://wiki.archlinux.org (its "AUR submission guidelines" page returned an Anubis bot-block on direct fetch today, so it is cited via search-indexed excerpts only).
- **Sources**: https://aur.archlinux.org/packages/catppuccin-konsole-colorscheme-mocha-git (2026-09-24), https://aur.archlinux.org/packages/konsole-gruvbox (2026-09-24), search-indexed excerpts of https://wiki.archlinux.org/title/AUR_submission_guidelines (2026-09-24, page itself blocked by Anubis).
- **Confidence**: partly verified — package precedent and account/SSH/push mechanics are corroborated by multiple sources, but the ArchWiki guidelines page could not be read directly to confirm every edge case (e.g. exact naming-policy wording).

## Open questions

- Which account submits to the KDE Store/Pling — a personal one, or one under the `shythulu` identity — and who holds its login long-term.
- Whether to bundle Darkberry as one Pling product (four flavours + four tints) or split per flavour/tint; unverified which convention the store prefers.
- Whether upstream Konsole maintainers want all four flavours (and possibly the four tints) bundled at once, or would rather take one exemplar scheme — worth asking in the merge request rather than assuming, given MR precedent (!1046) added only a single scheme at a time.
- Whether an MIT-licensed data file is acceptable inside the GPL-2.0-or-later Konsole tree as-is — not resolved by any policy document found; ask a Konsole maintainer before opening the merge request.
- For iTerm2-Color-Schemes: whether it's worth maintaining a second, hand-authored canonical source (`.itermcolors`/YAML) whose generated Konsole output must be kept in sync with `build.mjs`'s own output, or whether this venue should be skipped in favour of the KDE Store and upstream Konsole.
- For AUR: whether anyone on the project is willing to be the long-term AUR maintainer (SSH key custody, responding to comments/orphan requests), since AUR has no bus-factor-safe fallback if the maintainer disappears.
