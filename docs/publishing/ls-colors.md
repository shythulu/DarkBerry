# Publishing the LS_COLORS port

`ports/ls-colors/` holds four `darkberry-<flavour>.sh` files (Wisp, Fen, Mire, Blackwater) plus
a `<tint>/` subfolder per tint (blueberry, cloudberry, crowberry, lingonberry), each the same
shape. Every file is a plain shell script that exports a raw `LS_COLORS` string (the
`dircolors`/GNU-coreutils `extension=code:...` format), meant to be sourced from a shell rc file.

## Venues

### eza-community/eza-themes

- **URL**: https://github.com/eza-community/eza-themes
- **Kind**: community repo — the de facto theme gallery for `eza`, one of the port's named
  target tools; run by the `eza-community` GitHub org, which also publishes `eza` itself.
- **Accepts**: one YAML file per theme at `themes/<name>.yml` (flat, not a subdirectory — the
  README's "must be named `theme.yml`" note is about the *installed* symlink at
  `~/.config/eza/theme.yml`, not the repo filename). The schema styles broad sections
  (`filekinds`, `perms`, `size`, `users`, `links`, `git`, `git_repo`, `security_context`,
  `file_type`, `punctuation`/`date`/`inode`/`blocks`/`header`/`octal`/`flags`, plus optional
  `filenames`/`extensions` overrides for specific names/extensions and icons) using named ANSI
  colours or `"#RRGGBB"` hex — closer to Darkberry's category-based hues than to a flat
  extension map. A top-level `colourful: true|false` flag is optional. Metadata: none in the
  YAML itself; the README's `## Themes` list carries a one-line description and an `<img>`
  preview (existing entries use `width="500"`, no documented exact pixel spec) pointing at
  `imgs/<name>.png`, generated by running eza against the repo's own `test_dir/`.
- **Requirements**: a GitHub account to open a PR; no fee, no signing key, no formal
  CONTRIBUTING.md (checked, none exists — guidance lives in README.md's "Contributing"
  section). Licence is MIT (compatible with Darkberry's MIT). Review is informal maintainer
  PR review; recent merged PRs (2025-2026, e.g. #26 Kanagawa, #22 Catppuccin, #23 Solarized
  Dark) show new themes are still being accepted.
- **Steps**:
  1. Fork https://github.com/eza-community/eza-themes.
  2. Add `themes/darkberry-<flavour>.yml` for each of Wisp/Fen/Mire/Blackwater (four files),
     translating each flavour's hues into the `filekinds`/`file_type`/etc. sections.
  3. Render a preview per flavour from `test_dir/` and add it as `imgs/darkberry-<flavour>.png`.
  4. Add one bullet per flavour under `## Themes` in `README.md`, following the existing
     `- [name](themes/name.yml): Description.` + `<img>` pattern.
  5. Open a pull request against `main`.
- **Updates**: a follow-up PR editing the same theme file(s), image(s) and README line(s).
- **Contacts**: issues at https://github.com/eza-community/eza-themes/issues; org
  https://github.com/eza-community (also owns https://github.com/eza-community/eza).
- **Sources**: https://raw.githubusercontent.com/eza-community/eza-themes/main/README.md,
  GitHub Contents API listing of `/themes` and repo root, raw `themes/dracula.yml`, raw
  `LICENSE` (all fetched 2026-09-24); merged-PR history via GitHub search API (fetched
  2026-09-24).
- **Confidence**: partly verified — file format, location, licence and README instructions are
  confirmed live; whether the maintainers want all four flavours in one PR vs. four separate
  PRs, and the exact preview-image pixel size, are unverified (no written spec found).

### sharkdp/vivid (bundled themes)

- **URL**: https://github.com/sharkdp/vivid
- **Kind**: community repo — the official theme collection bundled with `vivid`, a separate
  `LS_COLORS` *generator* tool (not one of the port's four named target apps, but it produces
  the same `LS_COLORS` variable and is explicitly worth checking per the port's own README
  mention of related tools).
- **Accepts**: one YAML file per theme at `themes/<name>.yml`. The schema is a `colors:` block
  of named hex swatches (`RRGGBB`, no `#`) followed by a `core:` section keyed to dircolors
  slots (`directory`, `symlink`, `executable_file`, `broken_symlink`, etc.) and broader
  category blocks (`text`, `markup`, `programming`, `media`, `office`, `archives`,
  `executable`, `unimportant`) — a materially different shape from Darkberry's flat
  extension-to-code `LS_COLORS` string, since per-extension mapping lives in a single shared
  `config/filetypes.yml` that themes don't touch. Porting means re-deriving Darkberry's hues
  into these category buckets, not converting the existing `.sh` files directly. No required
  metadata fields in the YAML; the README's theme-preview table (`snazzy`/`molokai`/`ayu`/
  `lava`) is maintained ad hoc and not every bundled theme appears there.
- **Requirements**: a GitHub account; no fee, no signing key, no CONTRIBUTING.md (checked,
  404). Dual-licensed Apache-2.0 OR MIT (compatible with Darkberry's MIT). Review is informal
  maintainer PR review (maintainer: sharkdp / David Peter, who also publishes `fd` and `bat`).
  Recent merged PRs (2026, e.g. #201 Alucard, #200 cyberdream revisions, #190 ANSI theme) show
  new themes are still accepted.
- **Steps**:
  1. Fork https://github.com/sharkdp/vivid.
  2. Add `themes/darkberry-<flavour>.yml` per flavour, defining a `colors:` palette and styling
     the `core:`/category sections from it.
  3. Optionally add a table row to README.md's Preview section — existing entries are sparse
     and inconsistent, so this may not be expected (unverified).
  4. Open a pull request against `master`.
- **Updates**: a follow-up PR editing the same theme file(s).
- **Contacts**: issues at https://github.com/sharkdp/vivid/issues.
- **Sources**: https://raw.githubusercontent.com/sharkdp/vivid/master/README.md, GitHub
  Contents API listing of `/themes`, raw `themes/molokai.yml`, raw `config/filetypes.yml`
  (all fetched 2026-09-24); `CONTRIBUTING.md` 404 checked 2026-09-24; merged-PR history via
  GitHub search API (fetched 2026-09-24).
- **Confidence**: partly verified — file format, location and licence are confirmed live;
  whether the maintainer expects a bespoke palette (vs. the mostly well-known named palettes
  already bundled — Catppuccin, Gruvbox, Nord, Solarized, Dracula, Tokyonight, Rosé Pine,
  Kanagawa, Zenburn) is unverified, and no written acceptance criteria exist.

## Not applicable

- **trapd00r/LS_COLORS** (https://github.com/trapd00r/LS_COLORS) — not a multi-theme gallery:
  the repo is a single canonical `LS_COLORS` file (one extension-to-colour mapping shared by
  everyone), and its `CONTRIBUTING.md` (fetched 2026-09-24) only asks for missing file
  extensions to be added to that one file, not for alternate colour schemes. There is no
  `themes/` directory and no mechanism to list a separate named theme. Also licensed under the
  Perl Artistic License 1.0, not MIT.
- **Single-palette dircolors repos** (e.g. seebi/dircolors-solarized, arcticicestudio/
  nord-dircolors, peterhellberg/dircolors-jellybeans, ivoarch/dircolors-zenburn,
  KKPMW/dircolors-moonshine — all linked from vivid's own README as "similar projects") — each
  is one maintainer's personal repo for their own single palette, not a gallery that takes pull
  requests for other people's themes.
- **GNU coreutils `dircolors` project itself** — the manual page the port's own README already
  cites (https://www.gnu.org/software/coreutils/manual/html_node/dircolors-invocation.html) is
  documentation for the format, not a venue; GNU coreutils maintains no theme collection.
- **GitHub Topics** (`dircolors`, `ls-colors`) — tags repos for discovery, not a submission
  venue; a repo lists itself there by adding the topic, no review or acceptance involved. Not
  worth a dedicated section since it isn't a listing anyone submits *to*.

## Open questions

- Whether to submit all four Darkberry flavours to eza-themes and vivid in one PR each, or one
  PR per flavour — neither repo's history settles this consistently.
- Whether eza-themes/vivid maintainers will want the four *tint* variants (blueberry, cloudberry,
  crowberry, lingonberry) too, or only the base Darkberry flavours — likely only the base four,
  but that's a call for whoever opens the PR.
- Whose GitHub account opens these PRs (shythulu directly vs. another account) is for the
  submitting agent/human to decide.
- For vivid specifically: whether a bespoke, non-famous palette like Darkberry clears the bar
  set by the mostly well-known named palettes already bundled is unverified and worth a
  one-line pitch in the PR description.
