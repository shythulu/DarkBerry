# Publishing the darktable port

`ports/darktable/darkberry-<flavour>.css` is four standalone CSS files (`-wisp`, `-fen`, `-mire`, `-blackwater`), one per flavour, each meant to sit beside darktable's own `darktable.css` in its `themes` folder so the file's own `@import url("darktable.css")` header resolves; `ports/darktable/<tint>/` holds the same four files re-derived per tint (lingonberry/cloudberry/crowberry/blueberry). darktable reads any `.css` dropped into that folder and lists it by filename in Preferences > General > Theme — nothing to build, sign or register with the app itself.

## Venues

### darktable's own bundled themes (`data/themes` in darktable-org/darktable, GitHub)

- **URL**: repo https://github.com/darktable-org/darktable ; themes directory https://github.com/darktable-org/darktable/tree/master/data/themes ; contributing guide https://github.com/darktable-org/darktable/blob/master/CONTRIBUTING.md
- **Kind**: official gallery — anything merged here ships inside darktable itself and appears in every install's theme dropdown with no extra step from the user.
- **Accepts**: as of 2026-09-24 the directory (confirmed via the GitHub API tree listing) holds exactly ten full themes — `darktable.css`, `darktable-elegant-{dark,darker,grey,highcontrast}.css`, `darktable-icons{,-dark,-darker,-grey,-highcontrast}.css` — all first-party "elegant"/"icons" variants, plus ~20 small `chunk-*.css` files (accent-colour and module-border overrides meant to be pasted into the tweaks box or `@import`ed, not full themes). No third-party complete theme (Catppuccin, Nord, Dracula, etc.) is present in the directory. `CONTRIBUTING.md` lists welcomed contribution categories explicitly — Code, Documentation, Testing, Translations, Camera profiles, Tutorials/screencasts — and does not list themes as one of them. The whole repository is licensed GPL-3.0-or-later (confirmed by reading `LICENSE`), so a merged file would ship under that licence, not Darkberry's MIT.
- **Requirements**: a GitHub account to open a pull request; `CONTRIBUTING.md` says to discuss non-trivial changes first via the dev Matrix channel (`#darktable-dev:matrix.org`) or a GitHub issue before investing time, "especially if we think you'll hang around to maintain it" — i.e. an implicit maintenance-commitment expectation. No CODEOWNERS entry exists for `data/themes/` (checked `.github/CODEOWNERS`; only `rawspeed/` has an owner), so no single reviewer is pre-assigned.
- **Steps** (best-effort, since no theme-specific submission doc exists):
  1. Raise the idea first — a GitHub issue on darktable-org/darktable, or the `#darktable-dev` Matrix room — before opening a PR, per `CONTRIBUTING.md`.
  2. If encouraged, fork, add the flavour file(s) under `data/themes/`, and open a PR following the repo's coding-style/PR conventions (`.github/pull_request_template.md`, `AGENTS.md`).
  3. Expect review to weigh the GPL relicensing implication and long-term maintenance burden — darktable's internal CSS "changes frequently" per the user manual, which is likely why only in-house themes are currently bundled.
- **Updates**: a follow-up PR to the same file(s); merged changes ship with the next darktable release, no separate re-publish step.
- **Contacts**: GitHub issues https://github.com/darktable-org/darktable/issues ; dev Matrix room `#darktable-dev:matrix.org` ; general contact page https://www.darktable.org/contact/.
- **Sources**: GitHub API tree listing of `data/themes` (fetched 2026-09-24); https://raw.githubusercontent.com/darktable-org/darktable/master/CONTRIBUTING.md (fetched 2026-09-24); https://github.com/darktable-org/darktable/blob/master/LICENSE (fetched 2026-09-24); https://github.com/darktable-org/darktable/blob/master/.github/CODEOWNERS (fetched 2026-09-24); https://docs.darktable.org/usermanual/development/en/preferences-settings/general/ (fetched 2026-09-24, "changes frequently" maintenance warning).
- **Confidence**: partly verified. The directory contents, licence and absence of themes from the welcomed-contributions list are all directly confirmed. What is unverified is whether a well-made third-party theme PR would actually be accepted or declined — no explicit policy statement either way was found; the circumstantial evidence (only in-house full themes present, themes omitted from the contribution list, GPL relicensing) points toward this being a hard sell, but that is inference, not a documented rule.

### Darktable CSS (darktable-css.danielepighin.net, third-party community site)

- **URL**: https://darktable-css.danielepighin.net (also reachable over plain HTTP; both return 200) — themes list `/themes`, snippets list `/snippets`, install instructions `/instructions`, register `/register`, login `/login`.
- **Kind**: community repo — a small independent web app built specifically to host darktable theme files and CSS snippets with previews, separate from both darktable-org and pixls.us.
- **Accepts**: full theme CSS files (shown with one or two screenshot images each, e.g. the existing "GrayDarkerRoundedHeadersWithAccents" entry) and smaller CSS snippets. No licence field or licence requirement is stated anywhere on the fetched pages (register form, instructions page, themes list) — **unverified** whether it requires or records a licence for uploads.
- **Requirements**: free account — the register form (fetched 2026-09-24) takes `username`, `email`, `password`, `password_confirm`, and a numeric `captcha`; no email verification step was observed but can't be ruled out. The site is run solo by "Masterpiga" (Daniele Pighin), who described it in the pixls.us announcement thread as "a proof of concept" with "no guarantee that the service will stay up or that the db will not have to be reset" and said he'd be "happy to transfer ownership to the DT team" if the developers wanted it moved to official hosting — it has not been adopted officially as of 2026-09-24.
- **Steps** (partly inferred — the add-theme form itself sits behind login and could not be reached unauthenticated):
  1. Register at https://darktable-css.danielepighin.net/register (username, email, password, captcha).
  2. Log in; the themes list page shows a "Login to Add Theme" button when signed out, implying a matching "Add Theme" action appears once signed in — the exact form/URL is **unverified** (`/themes/create`, `/themes/new`, `/theme/create`, `/theme/new` and `/upload` all returned 404 unauthenticated, which is inconclusive either way).
  3. Upload the theme CSS file plus at least one screenshot per the existing entries' pattern.
- **Updates**: presumably edit your own submission while logged in (per-user ownership is shown via `/user/<name>` pages); exact edit/versioning flow unverified.
- **Contacts**: no email or about page found (`/about` returned 404); the pixls.us announcement thread (https://discuss.pixls.us/t/introuducing-darktable-css-a-theme-snippet-repository-for-darktable-theming/53642) is the de facto support channel, and the site's own registered users page (`/user/Masterpiga`).
- **Sources**: https://darktable-css.danielepighin.net/ , `/instructions`, `/register`, `/themes` (fetched via curl 2026-09-24, `WebFetch` was blocked by the site with HTTP 403, likely a bot check); https://discuss.pixls.us/t/introuducing-darktable-css-a-theme-snippet-repository-for-darktable-theming/53642 (fetched 2026-09-24, proof-of-concept/ownership-transfer quotes).

## Not applicable

The "contributing to dtdocs" pages (e.g. https://docs.darktable.org/usermanual/4.6/en/special-topics/contributing/) cover editing the manual's own text/screenshots, not listing third-party themes.
